MLP Fleet Dashboard

A single screen for a 45-truck fleet: where each truck is, what it carries and how the fleet performed this month.

Problem
GPS positions lived in the fleet system and dispatch plans lived in TMS exports. There was no TMS API, so nobody could see both together.
Built
It pulls vehicle positions from the FMS REST API and merges them with an uploaded TMS file. It matches trucks to customer geofences, calculates distances and adds driver, truck and trip analytics with Excel export.
Status
The codebase is complete. The company has paused API permission, so the live feed is offline for now. The analytics run on exported data.

Order Splitter with OCR

It reads a stack of mixed scanned pages and returns one clean PDF per order, plus a short pile of pages for a person to check.

Problem
Checking reports arrive as large mixed PDFs. Each page had to be filed by order number by hand, and scanner errors made the numbers inconsistent.
Built
Three detection methods: the PDF text layer, then QR codes, then Tesseract OCR. It adds confidence scoring, fixes irregular number formats, processes pages in parallel and includes a self-test suite.
Proof
On the sample bundle it sorted 10 of 11 pages into 5 orders. It sent the deliberately damaged scan to review instead of guessing.

REF PRJ-03SIZE 856 linesTYPE Python + AI vision
Built · working prototype

Hybrid Manifest Builder

It builds the shipment manifest in Excel from delivery notes and a handwritten loading checklist.

Problem
Manifests were typed by hand from GDN printouts and handwritten case and pallet counts. Customer codes often didn’t match the TMS codes.
Built
Local, rule-based parsing of GDNs with an embedded customer-code bank and fuzzy matching. Gemini vision reads only the handwriting, with multiple passes, and any disagreement is flagged.
Design choice
Delivery notes and code data stay on the PC. AI is used for the one step rules can’t do.
